Why Kitsune

Browser automation that works alongside you, not in your way.

“I built Kitsune after getting tired of switching back to my tab whenever my Playwright setup took focus, and opening Chrome for my agent when I already used a Firefox-based browser.”

{% include ".icons/material/tab-plus.svg" %}

Keep working while the agent works.

Agent-created tabs open in the background. Selecting a tab for the agent doesn't switch the tab you see.

{% include ".icons/material/hand-back-left-outline.svg" %}

Your tabs stay yours.

By default, the agent can read your tabs but cannot type, navigate, scroll or close them. It must request a handoff before changing one; you approve and can take it back.

{% include ".icons/material/firefox.svg" %}

Stay in Firefox, Zen or LibreWolf.

Reuse your existing sessions without opening a separate Chrome browser or installing WebDriver.

{% include ".icons/material/tools.svg" %}

A small tool surface.

Six tools: Python for browser actions, plus direct controls for user help and recovery.

Kitsune is designed to reduce interruptions, not eliminate them: site-opened popups and OS-level trusted input can still move focus. See the shared-browser limits.

How it works

Your browser. Your agent. One clever bridge.

The server, bridge and extension all run on your machine. No WebDriver, no separate browser.

  1. {% include ".icons/material/robot-outline.svg" %}

    Your agent

    Claude Code, Codex, Pi, Cursor or another MCP client launches kitsune over stdio.

  2. stdio
  3. {% include ".icons/material/console.svg" %}

    Local bridge

    The MCP server starts a bridge daemon on 127.0.0.1 when needed and talks to it with a bearer token. Several agents share one bridge.

  4. WebSocket
  5. {% include ".icons/material/puzzle-outline.svg" %}

    Your browser

    The Kitsune extension connects to the bridge and opens background tabs for the agent.

Benchmark

Four browser tools, two agents, 96 attempts.

Kitsune made the fewest tool calls and used the least input in a four-way comparison under two agents: Aside, EgoLite, Playwright MCP and Kitsune on 12 local web tasks, under Claude Code and Codex.

claude-opus-5-5 and gpt-6.1-sol, one attempt per task. Input includes cache, not billed cost. Kitsune missed one task under both agents: a native confirm() dialog blocked the click. Playwright MCP ran an isolated Firefox; the others used the operator's browser. Results, methodology and limitations →

Get started

Add Kitsune to your agent.

  1. Install uv

    uv provides uvx and Python 3.10+. Kitsune runs on macOS and Linux.

  2. Install the browser extension

    Download it for Firefox, Zen or LibreWolf from the same release as the server.

  3. Register the MCP server

    {{ command("Claude Code", install_claude) }} {{ command("Codex CLI", install_codex) }} {{ command("Pi", install_pi) }}

    Claude Desktop, Cursor and OpenCode are in Installation.

  4. Keep the browser open and ask in plain language

    Research these three products in background tabs and compare them with links. Leave my current tab alone.

Trust note

Python runs locally, not in a sandbox; set KITSUNE_SCRIPTING=0 to disable it. Approvals do not prevent prompt injection. Use a separate profile for sensitive accounts.
